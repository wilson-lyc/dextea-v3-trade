# 标记订单已取餐

## 接口说明

门店将订单从「制作完成」标记为「已取餐」，订单生命周期结束。前置条件：制作状态为「制作完成」，不满足时返回 `21027`。仅能操作归属本门店（`X-Store-Id`）的订单。成功后响应 `data` 为 `null`。

## 请求地址

```
POST /api/v1/store/orders/{orderId}/collect
```

路径参数：

| 参数 | 类型 | 说明 |
| ---- | ---- | ---- |
| orderId | long | 订单 ID |

## 请求头

| 请求头 | 必填 | 说明 |
| ------ | ---- | ---- |
| Authorization | 是 | API 访问令牌，格式 `Bearer {token}` |
| X-Store-Id | 是 | 门店 ID，标识当前门店 |

## 请求参数

无 Body 参数。

## 请求示例

```bash
curl -X POST http://localhost:8080/api/v1/store/orders/1/collect \
  -H "Authorization: Bearer {token}" \
  -H "X-Store-Id: 1"
```

## 响应格式

无业务数据，`data` 为 `null`。

## 响应示例

```json
{
  "code": 0,
  "message": "成功",
  "data": null
}
```

## 错误码字典

| 错误码 | HTTP 状态码 | 说明 |
| ------ | ----------- | ---- |
| 50000 | 500 | 系统繁忙，请稍后重试 |
| 50101 | 500 | 数据库访问异常（系统繁忙，请稍后重试） |
| 21016 | 400 | 订单不存在 |
| 21019 | 400 | 该订单不属于当前门店 |
| 21027 | 400 | 制作状态必须按 待制作→制作中→制作完成→已取餐 逐级变更 |
| 40001 | 400 | 缺少请求头 |
| 40002 | 400 | 参数缺失 / 参数类型不正确 |
| 40100 | 401 | 未登录 |
