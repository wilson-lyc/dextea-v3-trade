# 交付前自检清单

## 结构

- [ ] 文件位于 `docs/api/`，文件名为 `{端}-{资源}-{动作}.md`，小写中划线。
- [ ] 九个章节齐全且顺序正确：接口名称、接口说明、请求地址、请求头、请求参数、请求示例、响应格式、响应示例、错误码字典。
- [ ] 无自创章节、无缺失章节；无内容的章节写明「无 Body 参数。」「无业务数据，`data` 为 `null`。」等，而不是删掉。
- [ ] 一级标题为中文动宾短语，与代码接口语义一致。

## 内容与代码一致性

- [ ] 请求地址的方法与路径与 Controller 注解拼接结果一致。
- [ ] 请求头表格完整（含 `Authorization` 与身份头），与 `@RequestHeader` 一致。
- [ ] 请求参数表格的字段名、类型、必填性与 Request DTO 及其校验注解逐项一致；无遗漏字段、无已删除字段残留。
- [ ] 响应 `data` 字段表格与 Response DTO 逐项一致。
- [ ] 枚举取值与代码枚举一致，且与 `docs/api/README.md` 枚举字典一致。
- [ ] 接口说明写清前置条件、状态流转、幂等行为与副作用。

## 示例

- [ ] `curl` 示例可直接执行，含全部必需请求头与真实结构 Body。
- [ ] 响应示例为含信封的完整 JSON。
- [ ] 示例值贴近真实业务，无 `xxx` / `foo` / `test` 类占位串。
- [ ] `data` 有多种业务形态时分别给出示例。

## 错误码

- [ ] 只列本接口实际可能抛出的码，无无关码。
- [ ] HTTP 状态码列符合 `error-codes.md` 推导规则（`4` 开头取前 3 位；`2` → 400；`3` / `5` → 500）。
- [ ] 排列顺序为 `5xxxx` → `2xxxx`（升序）→ `4xxxx`（升序），与既有文档一致。
- [ ] 相关通用码已包含（至少 `40001`、`40002`、`40100`、`50000`、`50101` 中适用者）。
- [ ] 若本次改动新增或调整了错误码枚举，`docs/api/error-codes.md` 已同步，且分组正确（通用错误按参数/鉴权/资源/幂等/限流/系统/数据库/下游，业务错误按模块）。
- [ ] 新错误码的段位符合分段规范，未与既有码冲突，未复用历史空位。

## 索引与联动

- [ ] 新增接口已登记到 `docs/api/README.md` 对应端的表格。
- [ ] 路径 / 方法变更已同步索引表格。
- [ ] 错误码或公共约定变更已检查是否影响其他接口文档，受影响文档一并更新。

## 常见错误

- 照抄错误码枚举全集，把本接口不可能出现的码写进字典。
- 自行给错误码指定 HTTP 状态码，与统一推导规则冲突。
- 在单篇文档里重复解释响应信封或错误码分段规范，造成多处失真。
- 只改了接口文档，漏掉 `README.md` 索引或 `error-codes.md` 总表。
- 参数表格漏掉嵌套对象/数组元素的字段说明。
- 沿用旧字段名或旧枚举值，与重构后的代码脱节。
